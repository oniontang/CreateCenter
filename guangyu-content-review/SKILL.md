# guangyu-content-review：内容反馈复盘

把一条内容的真实反馈变成下一次创作的输入。复盘围绕用户当初想验证的问题展开，不把所有内容都按播放量排序，也不把表现好坏直接归因于某个标题、用词或Skill。

## 一、先确认本次复盘对象

复用已有对话和存档，确定：

- 内容版本：实际发布的是哪一稿，标题、开头、画面和发布时间是否与讨论版本一致。
- 原目标：希望受众理解、收藏、评论、咨询还是执行某项动作，是否有事先约定的内容实验。
- 平台和格式：视频、图文、文章，时长与受众范围。
- 数据来源：用户截图、表格、手工记录或已授权连接器，及数据获取时间和统计窗口。
- 可比样本：同账号、相近主题/格式、相同观察时长的历史内容；没有就明确不具备基线。

关键缺口会改变判断时，先问一个具体问题；次要信息不足不阻断已有范围的分析。没有发布材料时可以做版本准备检查，但不能称为发布复盘。

## 二、整理证据，先看清再解释

先读取 [数据口径](references/metric-rules.md)。至少分开以下层次：

1. **作品事实**：实际讲了什么、承诺是什么、核心例子在哪里；未看到成片时不判断画面与声音。
2. **平台观察**：真实给出的曝光、播放、留存、完播、收藏、分享、评论、关注或咨询；缺项留空，不填0。
3. **受众反馈**：评论原话、提问、误解、反对、实际使用结果；平台后台与评论不得相互冒充。
4. **用户判断**：用户满意或不满意什么，有哪些即使数据较好也不愿采用的表达。

保留平台原字段名、单位和采样时间。不同时间窗的数据不直接横比，播放和曝光、次数和人数也不混算。对外说明按用户需要使用自然语言，不堆不必要的指标。

## 三、围绕问题提出竞争解释

先按原目标判断完成到哪一步，再找证据支撑可能原因。

可按需要检查：

- 触达：内容是否主要触达目标受众，现有信息能否支持这个判断。
- 入口：标题与开头是否让人理解问题，是否与正文兑现一致。
- 内容：受众在哪些位置理解、误解、需要更多细节；有真实时间数据时再定位流失。
- 表达：评论是否能说明具体表达引起共鸣，不以单条夸奖代表全体观众。
- 制作：画面、声音、字幕或时长是否存在可观察问题，未检查的不下结论。
- 分发与情境：主题热度、账号阶段、发布时点、投放、样本大小等是否可能影响结果。
- 目标行为：用户期望的收藏、咨询或使用行为有没有证据，不把高播放自动等同商业效果。

每个主要判断写清“证据是什么、还有什么别的解释、怎么进一步分辨”。单条内容的波动通常不足以证明因果；小样本只提出待检验假设，不套用固定流量阈值。

## 四、保留有效判断，确定下一次实验

将结果分为四类：

| 类型 | 处理 |
| --- | --- |
| 已观察事实 | 保留数据、评论或作品位置 |
| 有支持的解释 | 写出适用范围和仍存在的不确定性 |
| 证据不足 | 写成待验证假设，不升级成方法论 |
| 用户明确的表达选择 | 记录选择与理由，不因数据随意否定用户立场 |

下一次优先检验一个关键变量，如开头的具体问题、案例展示方式或解释顺序；保持能保持的其他条件。不能严格控制变量时，说明这是创作实验，不是假装做了随机试验。

给少量互相区分的动作供用户选择，每项包含：改什么、为什么、需要什么素材、观察哪个结果、什么时候可以比较。已有约定直接复用；未约定时可建议观察窗口，但不自动建立定时任务。

用户确认后才把实验写成“已确认下一步”。不替用户承诺改变账号方向、追逐热点或照搬对标。

## 五、交付复盘卡

按 [复盘卡模板](templates/review-card.md) 交付，可按材料规模删减空泛栏目。必须保留：

- 复盘对象、原目标、实际版本和数据窗口。
- 可直接回溯的主要观察，明确未提供的部分。
- 主要解释与竞争解释，及结论强弱。
- 哪些动作值得保留，哪些内容仍需验证。
- 用户已经确认或尚未选择的下次实验。

没有反馈时交付“复盘计划”，不是“复盘结论”：列出发布后应收集的字段、来源、观察时间和要验证的问题。

## 六、与本套其他模块衔接

本模块负责反馈到下一次创作，不代替所有诊断。只有用户要深入对应问题时才提示：

- 不知道为什么已有内容引发共鸣：`guangyu-spread`。
- 具体稿件的共鸣或口播问题：`guangyu-resonate`、`guangyu-script-flow`。
- 重新判断选题：`guangyu-content-value`。
- 检查成片画面与声音：`guangyu-video-perception`，前提是有素材和可用工具。
- 保存用户确认的结论：`guangyu-save`；下次接续：`guangyu-restore`。

不要求用户返回总入口。用户只要复盘时就完成复盘；不自动调用后续模块、改稿或发布。

## 七、执行与数据边界

默认分析用户提供的材料。需要读取后台时，先检查已连接服务的实际能力与用户授权范围；没有连接器就处理用户提供的数据，不虚构后台采集结果。不读取密码或将密钥写进复盘文件。

评论和私信可能包含个人信息，仅保留必要短摘录，面向课堂展示时匿名化。没有取得授权的私人材料不自动上传到外部工具。

归档复盘不等于生成新Skill。一条内容总结出的规则先作为带条件的候选判断，经过多次真实任务检验后，再由用户决定是否制作或修改Skill。
